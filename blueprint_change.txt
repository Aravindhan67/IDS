### 3. Detailed Component Remediation

#### Component 1: Resolving the Static Feature Extractor Gap (46.5% Missing Features)
* **The Problem**: In naive implementations, parsing only `AndroidManifest.xml` extracts permissions, leaving:
  * 23 Intent actions (e.g., `android.intent.action.BOOT_COMPLETED`, `PACKAGE_REPLACED`, `SIG_STR`)
  * 77 Dalvik API calls and classes (e.g., `Ljava.lang.Class.forName`, `ClassLoader`, `TelephonyManager.getDeviceId`, `Runtime.getRuntime`, `System.loadLibrary`)
  permanently set to 0. This creates an artificial distribution shift between training and live inference.
* **The Remedy**:
  * Utilize `androguard.core.bytecodes.apk.APK` for manifest elements (permissions + intents).
  * Utilize `androguard.core.bytecodes.dvm.DalvikVMFormat` and `androguard.core.analysis.analysis.Analysis` to inspect all class references (`dx.get_classes()`), method invocations (`dx.get_methods()`), and string constants.
  * Implement an automated unit test `test_feature_extractor_coverage()` that scans real APKs and asserts that the ratio of extracted non-permission features is $> 0$.

#### Component 2: Resolving the Dynamic Sandbox Mock & Constant $P_d$
* **The Problem**: Returning Dalvik names like `sendTextMessage` when the dynamic model expects Linux kernel syscalls (`accept`, `bind`, `clone`, `ioctl`, `fork`) resulted in all-zero vectors. Thus $P_d$ was invariant, reducing the hybrid formula to $0.5 \cdot P_s + \text{const}$.
* **The Remedy**:
  * Align the dynamic feature schema with the 470 features of [feature_vectors_syscallsbinders_frequency_5_Cat.csv](file:///c:/ids/dataset/feature_vectors_syscallsbinders_frequency_5_Cat.csv) (150 Linux syscalls + 320 Binder/IPC categories).
  * In live environments: Attach `strace -f -e trace=all` to the app PID or configure Frida scripts intercepting `libc.so` and `libbinder.so`.
  * In offline evaluation: Implement a statistically grounded telemetry simulator sampling from real empirical distribution intervals of malware vs benign classes, explicitly labeled in the paper as **"Simulated Telemetry Protocol"** to maintain scientific credibility.

#### Component 3: Rigorous Handling of Unpaired Datasets & Hybrid Evaluation
* **The Problem**: Drebin (static) and CICMalDroid (dynamic) are disjoint datasets; merging row $i$ of Drebin with row $i$ of CICMalDroid creates synthetic chimera samples with no real-world validity.
* **The Remedy**:
  1. **Dual Independent Benchmarking**:
     * Report Static XGBoost metrics on Drebin (7,254 samples).
     * Report Dynamic XGBoost metrics on CICMalDroid (11,598 samples).
  2. **Cascaded Triage Evaluation (Two-Stage Architecture)**:
     * Evaluate Stage 1 (Static) at operating thresholds $\tau_1 = 0.35$ (benign cutoff) and $\tau_2 = 0.75$ (malware cutoff).
     * Quantify the percentage of traffic resolved with zero sandbox overhead ($P_s < \tau_1$ or $P_s > \tau_2$), and the fraction routed to dynamic sandbox execution.
  3. **Synthetic Paired Weight Sweep Ablation**:
     * Evaluate late fusion $P_{\text{hybrid}} = w_s P_s + (1 - w_s) P_d$ across $w_s \in [0.0, 0.1, \dots, 1.0]$ to evaluate sensitivity and Pareto-optimal balance.

#### Component 4: Class Imbalance & The SMOTE vs. `scale_pos_weight` Benchmark
* **Empirical Reality of Workspace Data**:
  * `drebin.csv`: 5,560 Malware (`S`) vs 1,694 Benign (`B`). **Benign is minority (23.35%)**.
  * `CICMalDroid`: 9,803 Malware (Classes 1–4) vs 1,795 Benign (Class 5). **Benign is minority (15.48%)**.
* **Methodological Protocol**:
  * Drop duplicate samples prior to splitting.
  * Use **Stratified 5-Fold Cross-Validation**.
  * Apply SMOTE **strictly on the training folds**.
  * Directly compare:
    1. Baseline (No resampling)
    2. SMOTE oversampling
    3. XGBoost native `scale_pos_weight` (cost-sensitive loss without synthetic artifact generation)
  * Citing recent research ([arXiv:2602.08744](https://arxiv.org/abs/2602.08744)), evaluate whether `scale_pos_weight` outperforms SMOTE on high-dimensional sparse tabular Android datasets.

#### Component 5: What-If Counterfactual Remediation (Core Novelty)
* **Design**:
  * Standard machine learning classifiers output an opaque probability.
  * Our remediation module connects **SHAP TreeExplainer** feature attributions directly to a **Counterfactual What-If Simulator**:
    1. SHAP identifies top-contributing malicious features (e.g., `SEND_SMS`, `SYSTEM_ALERT_WINDOW`, `READ_PHONE_STATE`).
    2. The simulator zero-masks these high-risk permissions sequentially.
    3. The model re-evaluates the modified feature vector:
       $$\Delta \text{Risk} = P_{\text{original}}(\text{Malware}) - P_{\text{counterfactual}}(\text{Malware})$$
    4. Provides least-privilege remediation recommendations to developers or MDM (Mobile Device Management) enterprise administrators without requiring binary recompilation.

### 4. Mandatory Experimental Matrix & Ablations

| Experiment ID | Configuration | Purpose | Expected Metrics |
| :--- | :--- | :--- | :--- |
| **EXP-1: Static Baseline** | Static 215 features, Drebin, 5-Fold CV | Assess static discriminative power | Acc, Prec, Rec, F1, ROC-AUC |
| **EXP-2: Dynamic Baseline** | Dynamic 470 features, CICMalDroid, 5-Fold CV | Assess runtime behavioral discrimination | Acc, Prec, Rec, F1, ROC-AUC |
| **EXP-3: Resampling Benchmark** | Compare No-SMOTE vs SMOTE vs `scale_pos_weight` on LR, RF, XGBoost | Answer Reviewer critique on class balancing efficacy | F1-Score, PR-AUC, False Positive Rate |
| **EXP-4: Feature Gap Ablation** | All 215 features vs 115 permissions-only | Quantify the performance penalty of missing 46.5% bytecode features | Delta F1, Delta ROC-AUC |
| **EXP-5: Dynamic Mock Ablation** | Flawed mock (constant $P_d$) vs Realistic dynamic | Prove the value of fixing the Reviewer 2 Point 1 bug | Delta Hybrid F1 |
| **EXP-6: Fusion Weight Sweep** | Late fusion with $w_s \in [0.0, 1.0]$ in increments of 0.1 | Identify optimal balance between static and dynamic signals | ROC-AUC curve vs $w_s$ |
| **EXP-7: Cascaded Triage** | Two-stage thresholding ($\tau_1 = 0.35, \tau_2 = 0.75$) | Measure latency and sandbox reduction rate | % Samples sandboxed, Triage Accuracy |
| **EXP-8: What-If Remediation** | Top-K SHAP permission masking on malware test set | Demonstrate practical security remediation utility | Average Risk Reduction ($\Delta P$) |
